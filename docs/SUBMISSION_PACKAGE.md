# Submission package

Prepare a source archive only when ready to submit. No archive, commit, deployment or data seed is created by documentation closeout.

## Include

- `app/`, `components/`, `lib/`, `public/`, `scripts/`, `docs/`
- `package.json`, `package-lock.json`, `tsconfig.json`
- `next.config.ts`, `postcss.config.mjs`, `eslint.config.mjs`, `vercel.json`
- `.env.example` with blank assignments only, `.gitignore`, `README.md`
- Root `AI_IMPLEMENTATION_SUMMARY.md` compatibility pointer
- `AGENTS.md`, `CLAUDE.md` if retained in the project checkout
- `TODAY_UPDATES.md` and original reports if retaining project history, clearly labelled historical

Include local assets and required imports. `next-env.d.ts` is generated by Next.js and is ignored; it is not an environment secret and need not be archived. Keep the lockfile so installation is reproducible. Historical scripts/reports can be included without executing them. No final database export or assessment account credentials belong in the public source package.

## Exclude

- `.env`, `.env.local`, every environment-value file except the blank `.env.example`
- `.git/`, `node_modules/`, `.next/`, `.vercel/`, build output and TypeScript build caches
- `coverage/`, Playwright reports, test-results, screenshots, traces and recordings
- temporary logs, local DNS preload/workaround files and OS/editor metadata
- private keys, credentials, tokens, database dumps and provider responses containing private data
- existing submission ZIPs and staging directories

Screenshots/report/video requested by the course should be supplied as separately reviewed assessment artifacts, not accidentally copied from test output. Inspect them for personal information first.

## Preferred PowerShell procedure: committed source

`git archive` packages a committed tree; it does **not** include uncommitted edits or required untracked files. It also does not magically filter tracked secrets using .gitignore. Therefore review the source manifest, confirm necessary source/docs are committed through the team's normal process, and check for prohibited tracked files before packaging. **The current closeout working tree is dirty; do not archive HEAD yet or it will omit final changes.** Closeout itself does not authorize or perform a commit.

Run from the repository directory after that prerequisite is satisfied:

```powershell
$pendingSubmissionChanges = @(git status --porcelain --untracked-files=all)
if ($LASTEXITCODE -ne 0) { throw 'Unable to read Git status.' }
if ($pendingSubmissionChanges.Count -gt 0) {
    throw 'Review and commit required source/docs before creating the final archive.'
}

# Review this list; ignore rules do not remove already tracked files.
git ls-files
if ($LASTEXITCODE -ne 0) { throw 'Unable to read the source manifest.' }

$submissionArchive = Join-Path (Split-Path -Parent (Get-Location).Path) 'internship-tracker-submission.zip'
if (Test-Path -LiteralPath $submissionArchive) {
    throw 'An archive already exists. Choose a new filename and review it separately.'
}
git archive --format=zip --output=$submissionArchive HEAD
if ($LASTEXITCODE -ne 0) { throw 'Source archive creation failed.' }

# Inspect entries without extracting or executing anything.
Add-Type -AssemblyName System.IO.Compression.FileSystem
$submissionZip = [System.IO.Compression.ZipFile]::OpenRead($submissionArchive)
try { $submissionZip.Entries.FullName } finally { $submissionZip.Dispose() }
```

Before sending, confirm the ZIP includes all required directories/configuration and only the blank environment template. Extract to a separate review directory and use the documented setup/check commands if a final reproduction check is required. Never run seed scripts as part of that check.

If commits are not yet permitted, keep working-tree changes intact and postpone archive creation; do not use a broad recursive ZIP of the project folder as a shortcut. A reviewed allowlist staging process is an alternative only when specifically needed.

## Git history and assessment access

A source archive contains no Git history. If the course requires collaboration history, provide the GitHub repository separately; the ZIP is not a substitute. Supply report/video/presentation through the required assessment channel. Provide authorized assessment access privately and never put passwords or real environment values in the public README, slides or ZIP.
